# 实现完整性规则

## 问题根源

在这个项目中反复出现以下问题：
1. **偷懒不做** — 被要求实现功能时，返回 501 或写占位代码，然后声称"已完成"
2. **对不齐** — 前端调用的 API 和后端实际接口完全不匹配（字段名、URL、请求格式全错）
3. **只写接口不实现内容** — 函数签名存在但内部逻辑是假的或空的
4. **和自己写的 design 对不齐** — 实现和设计文档描述的结构不一致
5. **骗用户已完善** — 子代理报告"已完成"就直接转述，不验证

## 强制规则

### 规则 1：实现必须完整

- 用户说"实现"就是要真正实现，不是返回 501、不是写 TODO、不是占位
- 如果技术上确实无法实现（比如需要外部服务），必须**立即告知用户**并说明原因，而不是假装做了
- 永远不要在用户明确要求实现的情况下返回 Not Implemented

### 规则 2：前后端必须对齐

写前端代码时：
1. **先读后端 handler 代码**，确认每个接口的：
   - 精确 URL（包括是否有尾部斜杠）
   - HTTP 方法
   - 请求体字段名和类型
   - 响应体结构和字段名
2. **先读 model 定义**，确认数据结构的字段名
3. **写完后对照检查**：前端用的每个字段名是否和后端返回的完全一致

### 规则 3：和 design 文档对齐

实现代码时：
1. 先读 `.kiro/specs/*/design.md` 中的相关部分
2. 确认接口签名、数据结构、流程和 design 一致
3. 如果实现需要偏离 design，必须先更新 design 文档

### 规则 4：子代理结果必须验证

- 子代理完成后，**必须读取关键文件**确认代码正确
- 特别是：前端 JS 中的 API 调用 URL 和字段名、后端 handler 中的路由注册、service 中的业务逻辑
- 如果发现子代理的实现有问题，**自己修复**，不要再次委托同一个任务

### 规则 5：不要声称完成未验证的工作

- "测试通过"不等于"功能正确"
- "编译通过"不等于"逻辑正确"
- 只有亲自确认代码逻辑正确后才能告诉用户"已完成"

### 规则 6：对照检查清单

每次修改完成后，问自己：
- [ ] 我读了被修改文件的最终内容吗？
- [ ] 前端调用的 URL 和后端路由完全匹配吗？
- [ ] 前端使用的字段名和后端返回的 JSON 字段名完全一致吗？
- [ ] 请求体格式（JSON vs FormData、字段类型）正确吗？
- [ ] 功能是真正实现了还是只是占位/假实现？
- [ ] 和 design.md 中描述的一致吗？

## 开发环境

### 操作系统和 Shell

- **当前环境是 Windows**，Shell 是 **PowerShell 5.1**
- 所有命令必须使用 PowerShell 语法
- 环境变量设置用 `$env:VAR = "value"` 语法
- 命令连接用 `;` 而不是 `&&`
- 不要假设有 `sudo`、`apt`、`yum` 等 Linux 包管理器
- 不要使用 bash 语法（如 `VAR=value command`、`export`、`&&`）

### Go 测试运行

- 本项目的 Go 代码目标平台是 **linux/amd64**（部署到 Linux 服务器）
- 但开发和测试在 **Windows PowerShell** 上进行
- 项目环境中 GOOS 可能默认被设为 linux，导致直接 `go test` 编译失败
- **运行测试时必须显式设置 GOOS=windows**：
  ```powershell
  $env:GOOS = "windows"; $env:GOARCH = "amd64"; go test -v -run "TestXxx" -count=1 ./tests/
  ```
- 这是因为测试本身在 Windows 上执行（读文件、跑断言），需要编译为 Windows 可执行文件
- **每次运行 go test 都要加上** `$env:GOOS = "windows"; $env:GOARCH = "amd64";` 前缀

### 测试框架

- Go 测试使用标准 `testing` 包 + `github.com/leanovate/gopter` 做属性测试
- 前端没有独立测试框架，通过 Go 测试读取 JS 文件内容做静态验证
- 运行所有前端 API 不匹配测试：
  ```bash
  go test -v -run "TestBugCondition_|TestPreservation_" -count=1 ./tests/
  ```

## 适用场景

这些规则适用于：
- 所有代码修改（不论是新功能还是 bug 修复）
- 所有涉及前后端交互的代码
- 所有子代理委托的任务结果
- 所有向用户报告"已完成"之前的验证
